# 报告结果复核与验证源码

双击 `RUN_VERIFY.bat`，或在本目录执行 `python -B verify_report.py`。仅需代码包既有 numpy/scipy 环境。入口使用包内相对路径，不读取C盘桌面，不接串口、不绘图、不运行新的检测、RTL、综合或布局布线。

## 本命令实际重新计算

1. 两份冻结输入、四份真实输出的混合分量、连续1562/1563拍样本节拍、实际bank/alpha轨迹；按原整数卷积/RNE/饱和重新验证actual_output为零LSB差异，再由原始实际输出计算主区间及稳定诊断NRMSE。结果对应21dB HYBRID配对的34.96086565%和32.38388063%相对降低。
2. 两个4096点组件RTL case的hard/fade输出与独立整数模型逐位核对；依照原129抽头、10kHz离线高通和[commit-128,commit+160)区间重算高频暂态能量比，约-35.76682843dB，并保留31样本（0.96875ms）完全进入新库的代价。
3. 直接解析原Gowin资源XML：独立双MAC为921 LUT+ALU、488 REG、2 MULTALU27X18、6 BSRAM；合并为986、523、1、7。说明节省一个原生乘加宏，同时增加逻辑/寄存器/RAM。不是整机净面积降低。

4. 从冻结的`frozen_operator_and_components.npz`复算表4(b)四路主区间衰减，以及8 ms窗、2 ms步进下的联合通过数、最长连续窗数和首次连续三窗结束位置。结果同时写入`verification_result.json`的`components`，逐窗明细写`component_windows.csv`。独立运行可用`python -B verify_components.py`，另写`component_verification_result.json`。

### 窗口坐标与报告计数

全部下标从0开始，区间为左闭右开。FIR固定延迟320样本：输入分量窗口`[s,s+256)`对应输出窗口`[s+320,s+576)`。只有源窗口完全落在四路干扰重叠区间内才纳入正式统计。各路衰减按`10log10(参考能量/输出能量)`，两探针按`10log10(输出能量/参考能量)`取绝对值；使用未舍入值比较20 dB和1 dB门槛。

- `report_global`为报告沿用的全局网格：`s=64*m`，即输出窗口右端为`576+64*m`。2 ms例两方案各224/231窗通过；8 ms例各242/248窗通过。
- `overlap_anchored_diagnostic`从四路最新出现样本重新取网格：`s=max(start_sample)+64*m`，仍补320点输出延迟。结果分别为224/231、242/249，额外一窗来自网格起点变化。
- `unshifted_output_coordinate_diagnostic`专门复现未补320点偏移的坐标用法，得到222/231、240/249；开头的窗口对应源信号尚未完全四路重叠，不作为正式分量联合证据。

两种合法网格均保留，报告采用第一种既有口径，不根据通过数选择窗口起点。主区间总能量衰减与逐窗通过是两类统计，不能互相替代。这些是既有配对仿真的离线复算，不是新增板测。

结果写 `verification_result.json`；输入、原始输出及原有成绩不修改。`manifest.json` 校验包内源及样本，历史清单保留在 `original_manifests`；公开副本仅将来源路径中的个人用户名替换为 `User`，同步更新元数据校验值，源码及数值数据不变。

## 源码与完整重跑范围

`reference_sources` 保存从V30冻结依赖清单抽取的未改动算法、输入生成、参考运算及RTL源码。单独的绘图程序留在支撑材料，不进入代码包。`rtl_testbench` 保存组件、完整处理核及面积对照的原始TB/源/ROM。当前生产RTL仍以代码包的 `../c4/rtl` 为准，历史验证源是独立冻结快照。

原始算法/测试脚本中的历史绝对路径是来源记录，不能直接当作新的入口运行。`legacy_path_map.json` 与 `resolve_legacy.py` 提供只读路径解析和原哈希检查；完整旧依赖清单保留，路径用户名已匿名化。部分完整旧评分/仿真流水线依赖较多，保留在 `../../../支撑材料/项目资料/09_RTL` 和 `../../../支撑材料/原始验证/D盘原记录`。需要完整旧流程时，代码与支撑材料须保持本项目相对结构一并保留；不要更改冻结数值和运行配置。

本次只重新评分/重放已有原始输出，没有重跑完整在线检测器、1024前端、RTL事件仿真或Gowin综合/P&R。完整重跑还需安装相应Verilator/Icarus、Gowin教育版及其官方仿真原语，并移植旧执行封装路径；本包不把上述未执行步骤标为已通过。原始TB、全部冻结依赖和既有执行身份记录用于复查，不是新的仿真成绩。

## 证据限制

1024参考前端预计算且计算等待取零，使用实际共同配置/队列/Q15系数/渐变/FIR后端；并非两套完整在线1024/512硬件或板端对比。同为21dB不代表相同虚警率。只支持所列固定动态输入，不能推广为普遍改善30%。

部分全过程中点超过1dB、部分20dB抑制及早期30ms目标未全部达到；原结果及失败保留。平滑降低的是指定高频暂态能量，不保证总恢复误差更低。合并FIR是子系统资源取舍，不推算整机节省比例。

代码包根目录运行`python -B validation/am_narrowband/verify_metrics.py`，核对16000点真实UART板测及同输入1024冻结输出，从样本重算报告的206.57%／266.91%及22.61%相对降低，保留稳定40.20%／37.38%的负面对照。此命令与上文旧`RUN_VERIFY`分开，不重新运行算法、RTL或板测。资料均在本代码包内，原始历史路径只作来源说明。详见`am_narrowband/README.md`。
