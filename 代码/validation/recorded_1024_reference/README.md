# 实录混合样本的1024点软件参考

本目录复核报告中的同输入对比，输入为接收实录目标加人工窄带干扰。512方案使用实际FPGA UART回传，1024方案使用有限精度软件参考。两者层次不同，不是两套1024/512板端硬件实测，也不是只改变窗长的单变量实验。

## 运行

在代码包根目录安装既定Python3.12环境后运行：

```powershell
python -B validation/recorded_1024_reference/run_reference.py
```

也可使用代码包的`.venv/Scripts/python.exe`。脚本从自身位置寻找代码包根，依赖均在本包，无需桌面或D盘支撑资料，不连接串口，不需要Gowin、Verilator或1024硬件。

脚本使用`real_recorded_inputs/prepared/drm_recorded_two_pairs/input.npy`，实际512记录取自`host_ui/captures/c4_20261027_223556_432532/`。输入固定64000点、32kHz，payload SHA256为`f7273ee103dedc1a4a49282317bf0fd88425d1408b2abdc316b29c7daee03358`。只有混合int16样本进入1024检测与FIR；参考目标和启停标签在软件输出生成后才供离线评分使用。

## 冻结方法

1024点周期Hann，64样本步进（2ms），1～7kHz，3.90625Hz估频网格；原整数FFT/DTFT与21dB原始局部谱功率比准入。背景采用左右187.5～750Hz各19点功率中位数中的较大值，保留原归一化、功率下限及并列选择规则。一次强观测准入，两次缺失退出；最多4中心。不重新调门槛。

系数与滤波沿用冻结的Q15响应权重计算、641抽头18位/Q16合并FIR、32样本新旧输出渐变、同一连续输入历史、RNE及饱和。`source_manifest.json`记录原源码SHA256、ROM和提取的函数。数值函数原文不改，仅以原AST加载指定函数并显式绑定已有数值依赖，避开无关旧评分器的历史路径导入。

先以`backend_reuse_fixture.npz`及原更新轨迹复核旧软件输出、系数库和渐变轨迹，要求逐位一致，然后处理本次新输入。这项检查是旧软件后端复用核验，不是新的硬件验证。

软件1024在完整窗口结束后立即给出观察与配置，FFT/DTFT、系数准备的计算等待均为零；切换期间只保留最新待执行配置。板端512有真实分析、授权、配置队列与提交耗时。因此不能用本实验推算1024硬件资源、响应周期或宣布板端对比获胜。相同21dB数值门槛和物理背景范围也不证明虚警率相同。

## 本次结果

固定补偿320样本（10ms），不拟合增益、不补缺失输出，NRMSE相对同增益未人工加干扰的原实录参考计算。参考本身含接收噪声、信道和导频，并非无噪声发射真值。

| 评价区间 | 512实际板测NRMSE | 1024软件NRMSE | 512相对误差变化 |
|---|---:|---:|---:|
| 全段公共0～1.99s | 105.060124% | 127.502390% | 降低17.601447% |
| 稳定0.4～1.2s | 16.738723% | 16.263575% | 增加2.921548% |

稳定段512比1024高0.475148个百分点，不应写成稳态全面占优。全段包含干扰进入和退出过程；稳定指标不能替代全段。本次985观测、25次软件配置更新，系数保护失败和输出饱和均为0。只对本条固定输入成立，不能替代原报告其他两组输入，不能推广为统一降低30%。

`paired_metrics.csv`、`results.json`记录指标及限制；`raw_observations.json`、`decisions_1024_21db.json`保留在线参考决策；`output_1024_software.npy`为本次软件输出，`backend_state.npz`保留系数及逐样本渐变轨迹。图片、截图和绘图脚本在代码包外的报告支撑材料。
